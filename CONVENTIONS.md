# Conventions

Stable rules for every device in this repo. Device-specific state lives in `devices/<name>/HANDOFF.md`.

## Target and delivery

- Live 11 on an Intel Mac: Max 8 (Live's bundled version), the old ES5 `js` engine (no `let`, arrow functions, classes, template strings).
- Devices are audio effects (audio in → audio out).
- Engines are C++ (header-only C++17, no Max dependencies) so the exact code is tested offline on Linux (`tools/tests`); the Max wrapper is thin. Same setup as `mgrigonis0/wanderer-synth` (`devices/wanderer/`): copy its proven CMake, wrapper, `tools/build_device.py` and CI patterns rather than inventing new ones. No third-party Max packages.
- A device ships as one folder (`<Name>/`): the `.amxd`, its JS views and its external. GitHub Actions builds the external for Mac (universal: Intel + Apple Silicon), packages the folder and publishes it as a release zip ("<device> — latest build"). The user downloads it, unzips the folder into `~/Documents/Max 8/Library/`, runs `xattr -dr com.apple.quarantine` on it once per download, and drops the `.amxd` into Live.
- The `.maxpat` / `.amxd` are generated by `tools/build_device.py`: never hand-edit them.
- Every build bumps a version string printed to the Max console at load (`<device>: <part> <YYYY-MM-DD><letter>`), so the user can see which files Live loaded.
- After replacing an external, the user quits Live completely (Live keeps a loaded external in memory), then loads a fresh copy of the device (a copy saved inside a set keeps the old layout).

## Working with the user

- Roles: the user is the idea manager (what it's for, how it should feel, what sounds right, yes/no). Claude does the technical heavy lifting: research, measurement, processing design, how controls behave, the build. Bring a concrete recommendation with a one-line reason, not open questions; ask the user only about intent, feel and taste.
- The user wants to understand, not be in the dark, but can't take in large amounts at once: give a short plain-language digest per decision (what it does, why, what you'd hear); keep the full detail in the repo docs; explain more when asked.
- Nothing semi-decided is sacred: redesign whenever it gives a better result, and say so.
- Discuss and propose first; build only after an explicit "go".
- Short replies, short bullets. One decision at a time, and settle each step fully before moving to the next: don't rush ahead.
- Answer the user's questions before doing anything else.
- Explain in plain words with small examples.
- The UI comes first: show a mockup and get it approved before any final build.
- Keep Live test requests minimal: simulate and test offline first; ask for a Live test only when nothing else can tell.
- Every processing method must earn its place with a measured improvement in an offline test.
- Commit every build to GitHub; push when the user agrees.

## Naming and isolation

- Every buffer, dict, send/receive, Global and named object that is shared inside a device starts with `---` (Live replaces it with a per-device id). Nothing device-wide may use a fixed name: duplicate devices must never crosstalk.
- UI → `prepend <name>` → one receiver per role (e.g. `---brain`).

## Threads (C++ engines)

- Max's `z_dsp.h` defines `PI` (and `TWOPI`) as macros: never name an engine constant `PI` (Lifegiver uses `kPi`). The
  wrapper can be syntax-checked on Linux against max-sdk-base with stub `MacTypes.h`/`libkern/OSAtomic.h`.
- Long work (analysis, solving) runs on a worker thread owned by the external: `Host::post(work, done)`, `done` runs
  on the main thread from the clock; results carry a generation number so stale ones are dropped.

- The audio thread never allocates, locks or frees. The main thread talks to it through a command ring; it answers through a report ring; big data (tables, buffers, plans) is handed over by pointer and freed back on the main thread. An offline test counts allocations during `process()` (must be 0).
- Continuous values (knobs, amounts) go to the audio thread as atomics, latest value wins, read once per block: a ring can fill while audio is stopped and drop the newest value. Rings are for events.
- Values that arrive before audio starts (a set loading, audio restarting) apply at once; later changes glide.
- Every fade is S-shaped (smoothstep, or two one-pole stages for continuous controls: S-shaped and smooth when retargeted mid-glide), at least 3 ms: no corner in the level, no click. The offline click test must pass.
- The second-difference click measure is only valid on low tones (a clean sine above ~1 kHz at 44.1/48 kHz trips it by itself): test fades on low tones, and check the gain curve directly (no jump, no corner).

## gen~ rules (learned the hard way, if gen~ is ever used)

- gen~ can compile a whole engine to zero output with no console error. Keep new code in patterns already proven in a playing engine; if sound disappears, bisect against the last playing version.
- Functions first. Loops only at top level; a loop that should not run gets length 0, not an enclosing `if`.
- Inside loops, all peeks first, then logic.
- No nested ternaries. Declare every local once, at top level, before use.
- In Live, writes (`poke`, History) inside `if` blocks can be dropped. Make writes unconditional; choose the value or the target index with ternaries.
- Don't call user functions with side effects (e.g. an RNG) inside `if` blocks.
- Brain → engine requests: the brain counts a request number up; the engine acts once when the number changes. The engine never writes a slot the brain writes.

## Saving in the Live set

**Proven in Live 11.3 (Lifegiver 15e, 2026-10-16):** a hidden `[pattr state]` blob parameter holding a number list is saved in the set and restored on reopen, per device, no crosstalk. The recipe for a generated device:
- **Parameter mode of a plain object (`pattr`, `dict`) goes in `saved_object_attributes`**, as Max writes it: `"saved_object_attributes": {"parameter_enable": 1, "parameter_mappable": 0}` (plus the box-level `"parameter_enable": 1`). A box-level `parameter_enable` alone only works for UI objects (`live.dial` etc.); on a pattr it is silently ignored: the pattr still holds its value during the session, but Live saves an **empty blob** (`<MxDBlob><Blob /></MxDBlob>` in the `.als`), so everything is lost on reopen. This was the cause of Lifegiver 15a–15d (and wanderer-synth's State pattr has the same mistake).
- The pattr gets `"varname": "<its name>"`; `saved_attribute_attributes.valueof`: `parameter_type` 3 (blob), `parameter_invisible` 1 (Stored Only), **Initial Enable 0 and no `parameter_initial`** (the proven combination; whether Initial Enable on also works is untested).
- Live restores the value at once when the device loads (before `live.thisdevice` fires). Still ask more than once on load and save nothing until it is settled: it costs nothing.
- Debug tip: a `.als` is gzip'd XML. `gunzip -c set.als` and look at the device's `<BlobSlot>`: empty `<Blob />` means nothing was stored.
- Never a dict name in a pattr: a pattr given `dictionary <name>` saves only the name, `---` names change on reload, and the old name can point at another device's dict (Lifegiver 15a).
- An unnamed `dict` with parameter mode (also in `saved_object_attributes`, with `"embed": 0`) was restored too in 15e; one store is enough, prefer the pattr.
- No new symbols per save (Max never frees symbols): encode text as character codes.
- Keep old sets opening: new Live parameters go at the end of the generator's list, and saved arrays (plans, tables)
  only ever grow at the end, so an older set reads as a prefix and new values get neutral defaults.

## Max JS rules

- Keep view files plain ASCII: non-ASCII text in strings as `\u` escapes (Max reads the file's bytes as they are).
- Offline check (no npm here: the registry is blocked by policy): `node tools/ui/check_view.js` runs the view in a mock
  `mgraphics` (ES5 check, every state painted, clicks/drags → messages); `tools/ui/render_view.py` draws the recorded
  calls with cairo (ctypes, the library mgraphics is built on) to a PNG for comparing with the mockup.

- Dicts turn 1-element arrays into scalars; no nested arrays, no `null` (use a converter like `toArr`).
- Use `Object.prototype.toString` checks, not `instanceof Array`.
- `save` is a reserved function name.
- Long work runs in chunks via `Task`, so Live never freezes.

## Patching

- A comma in a message box splits the message.
- `[t a a]` can send the symbol "a"; fan out with plain patch cords instead.
